# Vesktop Plugins

Vesktop（Vencord）用のユーザープラグイン集です。配布パッケージには以下のプラグインが含まれます。

| プラグイン | 内容 |
|---|---|
| **VesktopChatExporter** | サーバー・DM・スレッド・フォーラム投稿のログをTXT/HTMLへ書き出し |
| **VesktopStreamQuality** | 画面共有（Go Live）とWebカメラの解像度・FPS・ビットレートを指定 |

---

## VesktopChatExporter

Vesktop起動中に受信したサーバーメッセージを専用フォルダーへ自動保存します。また、サーバーメニューから**現在のアカウントが閲覧できるテキストチャンネル**の過去ログを一括取得できます。

**DM・グループDM、スレッド、フォーラム／メディア投稿に対応**しています。受信したDMの自動保存、DM履歴の自動収集、DM右クリックからの一括保存ができます（設定でオフにもできます）。

- `.txt`：検索・加工しやすいプレーンテキスト
- `.html`：チャンネル一覧付きでブラウザ閲覧できるログ

ログは保存確認なしで、専用フォルダーへ直接保存されます。

```text
C:\Users\<ユーザー名>\Documents\VesktopChatLogs
├── <サーバー名>_<サーバーID>\        ← サーバーログ
├── Live\<サーバーID>\<チャンネルID>\  ← 今後の重複除外・古い順のリアルタイムログ
└── DMs\
    └── <相手／グループ名>_<DMチャンネルID>\   ← DMログ
```

## 重要事項

- 自動保存はVesktop起動中にクライアントが受信した新規メッセージが対象です。プラグイン導入前やVesktop終了中の履歴は、サーバー／DMメニューの一括保存で取得します。
- DMログには相手の私的な発言が含まれます。取り扱いには十分注意してください。不要なら設定の「DM自動保存」「DMを含める」をオフにできます。
- Discordの通常クライアントAPIを現在ログイン中のユーザーとして使用します。Botトークンやユーザートークンの入力・保存は行いません。
- 閲覧権限がないチャンネル、削除済みメッセージ、取得できないスレッドは保存できません。
- 大規模サーバーでは取得に長時間かかります。Discord APIのレート制限を避けるため、ページ間に待機時間を設けています。
- ログには個人情報が含まれる場合があります。保存・共有はサーバー規約、Discord利用規約、適用法令および参加者のプライバシーに従ってください。
- Discord/Vencordの非公式改造環境です。利用は自己責任です。

## インストール

### かんたんインストール（Releases・推奨）

[Releases](../../releases) から `VesktopPlugins.zip` をダウンロードし、展開して `install.bat` をダブルクリックします。

```text
VesktopPlugins.zip
├── install.bat        ← ダブルクリック
├── install.ps1
├── uninstall.ps1
├── README.txt
└── vencordFiles/      ← 各プラグイン入りの Vencord ビルド
```

インストーラーは以下を行います。

1. Vesktop のデータフォルダー（`%APPDATA%\vesktop` など）を自動検出
2. 既存の Vencord ファイルを `vencordFiles.bak-<日時>` へバックアップ
3. 同梱の Vencord ビルドを `sessionData\vencordFiles` へコピー

その後 **Vesktop を完全に終了して起動し直し**、`設定 → Vencord → Plugins` で使いたいプラグインを有効化します。

元に戻すときは `uninstall.ps1` を実行します（バックアップから復元、無ければ公式 Vencord を再取得）。

> Vesktop を更新した場合や `--repair` を実行した場合は公式 Vencord に戻るため、再インストールが必要です。

### 手動でビルドする場合

Vencord公式ビルドは外部プラグインをそのまま読み込みません。Vencordをソースからビルドします。

1. Vencordソースを取得します。
2. このリポジトリのプラグインをVencordへコピーします。

```powershell
Copy-Item -Recurse .\src\plugins\vesktopChatExporter <Vencord>\src\userplugins\vesktopChatExporter
```

`src/userplugins` が使えないバージョンでは、次へコピーしてください。

```text
<Vencord>/src/plugins/vesktopChatExporter
```

3. Vencordの手順に従って依存関係を導入し、Vesktop向けにビルド・注入します。
4. Vesktopを再起動し、`設定 → Vencord → Plugins` で `VesktopChatExporter` を有効化します。

同梱パッケージを自分で作り直す場合は次を実行します（要 git / Node.js 22+ / pnpm）。

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build-vencord.ps1
```

生成された `release\vencordFiles` を `installer` フォルダーと一緒に zip にします。

## 使用方法

### サーバー

1. サーバーアイコンを右クリックするか、サーバー名のメニューを開きます。
2. **全チャンネルのログを保存（TXT + HTML）** を選択します。
3. 完了後、TXTとHTMLが `ドキュメント\VesktopChatLogs` へ保存されます。

### DM・グループDM

1. DM一覧の相手を右クリック（グループDMはグループを右クリック）します。
2. **「<相手名>」のログを保存（TXT + HTML）** を選択します。
3. ログは `ドキュメント\VesktopChatLogs\DMs` へ保存されます。

同じメニューの **ログ保存フォルダーを開く** で保存先を開けます。取得中は同じメニューから中止できます。

### 保存されるファイル

**全チャンネルのログを保存（TXT + HTML）**（DMでは「〈相手名〉のログを保存」）を実行すると、保存先へ次を作ります。

- `<名前>_<ID>_<日時>.txt` / `.html`：全チャンネルをまとめた読みやすいログです。チャンネル内は常に**古い順**で、APIが最新側から返すページも並べ直して書き出します。
- `<名前>_<ID>_<日時>.manifest.json`：その実行の結果（完了／一部のみ／中止、対象数、保存チャンネル一覧と数、保存件数、取得できなかった理由）を記録します。
- `.manifest.json` は開始記録と終了記録を結合した1つのJSONです。まとめTXT/HTMLの書き込みが完了してから原子的に更新し、未完了の実行を完了扱いにしません。
- まとめログの見出し、HTMLのサイドバー、最終チャンネル一覧は、取得後に**権限を再確認して残ったチャンネル**だけから作ります。実行中の `.manifest.json` は保存済みページ・cursor・件数・処理段階を保持し、取り消された対象はcheckpointからも除外します。
- `<名前>_<ID>_<日時>.parts/<チャンネルID>/<最古のID>_<最新のID>.jsonl`：取得した1ページ（最大100件）ごとのJSONです。**取得と同時にディスクへ書き出し**、全件をメモリへ展開しません。長大なサーバーでも保存に失敗しにくく、途中で失敗・中止してもそこまでに取れたページは残ります（まとめログはこのJSONから作られます）。権限が途中で取り消されたチャンネルは、この実行の分のJSONを削除してまとめログにも含めません。**IDや名前はどこにも記録せず**、件数だけを結果に残します。

> すでに自動収集が保存した `History` フォルダーの中身（`最古のID_最新のID.txt` / `.html`）は、従来どおり1ページ1ファイルです。

まとめ書き込み中にも権限・停止リストを再確認します。書き込み途中で対象が失効した場合は、その実行のページと空フォルダーを削除し、TXT/HTMLと目次を残った対象から作り直します。組み立て中は `.txt.partial` / `.html.partial` に書き、両方を閉じて整合性・権限を確認してから最終TXT/HTMLを公開します。ページ欠落・読取失敗・片方だけの書込失敗は完了扱いにせず、manifestへ失敗を記録します。

新しい実行はページごとにcursor・件数・処理段階をcheckpointします。中断・再起動後、**同じ既存の保存ボタン**を押すと、その対象の未完了実行があれば保存済みページとcursorを使って続きから取得・再組み立てします。名前変更では保存場所を変えません。再開時には現在のチャンネル一覧・権限・停止リストを再確認します。過去版のcheckpointがない実行は自動再開対象ではありません（旧ファイルは変更しません）。

取消データの削除がディスクのアクセス拒否などで失敗した場合は、完了扱いにせず失敗を記録します。再開時は、この未完了実行のpartsにある未追跡のチャンネルディレクトリも確認し、孤立したページを削除してから続行します。アクセス拒否が続く間は削除を保証できず、権限を回避する処理は行いません。

## 設定

- **添付ファイルと埋め込みのURLを出力する**：添付そのものではなくURLをログへ記録します。
- **APIページ取得間隔**：100メッセージ取得ごとの待機時間です。標準は750ms、最低500msです。自動調節がONのときは、この値が**下限**になります。この間隔で自動収集が動き続け、履歴の最後（最古のメッセージ）まで到達すると、そのチャンネルは完了として記録されます。
- **取得速度の自動調節**：ONのとき、上の間隔を下限として取得速度を自動で調整します。HTTP 429や失敗が起きたら間隔を倍にして減速し、成功が続くと徐々に加速して下限まで戻します（上限10秒）。固定速度で動かしたいときはOFFにします。
- **自動保存**：Vesktop起動中に受信したサーバーメッセージを、日付・チャンネル別のTXT/HTMLへ追記します。
- 今後のリアルタイム保存は `Live/サーバーID/チャンネルID/日付.txt` / `.html`（DMは `DMs/Live/DMチャンネルID/DMチャンネルID/`）です。日付ごとの `.records` に確定メッセージIDをキーとして保存し、再起動・再送でも同IDを二重保存しません。通常は追記し、到着順が前後したとき・再起動後は1件ずつ読み戻して古い順へ再構築します。古い保存済みログは読み替え・並べ替えしません。
- **DM自動保存**：受信したDM・グループDMを `DMs` フォルダーへ追記します。
- **強制履歴収集**：閲覧できる全サーバー・全チャンネル・全スレッドの履歴を、最古のメッセージまで自動で取得し続けます。保存は常に**古い順**で、各チャンクはファイル名が `最古のID_最新のID`、本文も古い順に並びます（取得はAPIの都合で最新側から低速に遡ります）。保存先は `サーバー名_ID/History/チャンネル名_ID/` です。手動保存・スレッド列挙と共通の直列キューで原則1秒以上に1リクエスト、10回ごとに5秒休止し、HTTP 429時は即停止してDiscord指定時間以上待機します。スレッドのアクティブ一覧はチャンネルごとの検索APIで列挙し、バックグラウンド収集では混雑を避けるためテキスト／告知チャンネルを上限つきで巡回します（フォーラム／メディアは毎回）。進捗は再起動後も引き継ぎます。
- **DMを含める**：履歴の自動収集にDM・グループDMも含めます（一括保存は個別メニューから）。
- 初回の過去履歴完了後も、最新側から高waterまで差分を補完します。Vesktop終了中の新着が `completed` によって永久に飛ばされることはありません。古いbackfill cursorとは別の `newest` / `catchup` checkpointを使い、既存の進捗・未知フィールドを保持します。手動保存中は背景収集がページ境界で譲り、設定OFF中もI/Oなしの準備確認を残すためONへ戻すと再開できます。1回の収集は要求数で有界にし、対象を順番に巡回します。
- 親チャンネル／フォーラムを停止すると、その配下のスレッド／投稿も停止します。スレッドの右クリックから個別停止もできます。
- **停止するサーバーID / 停止するチャンネルID**：ここへ追加したサーバー・チャンネル・DMはログ収集を一切行いません（後述）。

## 指定したサーバー・チャンネル・DMのログ停止

サーバー単位・チャンネル単位・DM単位でログ収集を止められます。停止した対象は次のすべてに適用されます。

- 受信メッセージの自動保存（DM含む）
- 起動中の履歴の自動収集（実行中のチャンネルはその場で中断）
- サーバー／DMメニューからの一括保存
- Vesktop Consent Recorder による通話・画面共有の録画

設定する方法は4つあります。

1. **サーバーを右クリック → 「このサーバーのログ収集を停止」**
2. **チャンネルを右クリック → 「このチャンネルのログ収集を停止」**
3. **DMを右クリック → 「このDMのログ収集を停止」**
4. **設定 → VesktopChatExporter → 停止するサーバーID / 停止するチャンネルID** にIDを直接入力（DMのIDもここに入ります）

IDは17〜20桁の数字で、カンマ・改行・空白のいずれでも区切れます。もう一度同じメニューを選ぶか、設定欄から該当IDを消すと収集を再開します。

> 録画側（Vesktop Consent Recorder）はこの停止リストをそのまま読み取るため、同じ対象で通話録画も停止します。

## 現在の制限

- 添付ファイル本体はダウンロードしません。
- DMは「全DMを一括保存」ボタンがなく、個別の右クリック保存か自動収集のみです。
- スレッドはアクティブとアーカイブ済みを列挙し、フォーラム／メディアは親ではなく各投稿を取得します。アクティブ一覧はユーザーアカウントで使えるチャンネル単位の検索API（`/channels/{id}/threads/search`）を使用し、返る202（索引未準備、`code:110000`）は指定時間待って自動で1回だけ再試行します。非公開スレッドは現在の権限で取得できるもののみ（通常は参加済み、管理権限があれば管理可能なもの）です。
- 閲覧・履歴参照権限が必要です。参加・招待・アーカイブ解除・権限変更は行いません。
- 一部の一覧や履歴の取得が失敗した場合は「不完全」と表示します。削除済み・アクセス不能な内容は取得できません。
- DiscordやVencord内部APIの変更により、将来修正が必要になる場合があります。
- 履歴の取得・まとめTXT/HTMLの組み立ては1ページずつディスク経由で処理します。ただし数百万件の単一HTMLをブラウザで開くと、閲覧側では大量のメモリを消費する場合があります。

## 開発時の確認

```sh
npm ci
npm test
```

テストはDiscord API境界だけをfixtureへ置き換えて実プラグインを実行します。DM・スレッド列挙（チャンネル検索APIのオフセットページング、202再試行、巡回ウィンドウ）、アーカイブカーソル、権限・停止・429・一部失敗を確認し、native保存テストでは `TMPDIR` 配下へ実際にTXT/HTMLを書いて読み戻します。実アカウントや実チャットは使いません。

既存Vesktopを更新するときは、他のユーザープラグイン（ConsentRecorderなど）と `--disable-updater` の有無を維持してください。Main／Preload／Renderer／CSSを同一ビルドから一式で更新し、設定・停止リスト・収集進捗は削除しないでください。

# VesktopStreamQuality

画面共有（Go Live）とWebカメラの画質を指定するプラグインです。Discord本体のメディア品質設定を直接上書きします。

## 設定できる項目

### 画面共有（Go Live）

- **画面共有の画質を指定する**（オン/オフ）
- **解像度**：720p / 1080p（既定）/ 1440p / 2160p
- **フレームレート**：30 / 60（既定）/ 120 fps
- **最大ビットレート**：4 / 8（既定）/ 12 / 20 Mbps

### Webカメラ

- **Webカメラの画質を改善する**（オン/オフ）
- **解像度**：720p / 1080p（既定）/ 1440p
- **フレームレート**：30（既定）/ 60 fps
- **最大ビットレート**：2.5 / 4（既定）/ 8 Mbps

カメラ設定を変更したあとは、設定内の **「Webカメラ設定を今すぐ反映」** を押してください（次に通話へ入るときに適用されます）。画面共有の設定は次に配信を開始したときから適用されます。

## 仕組み

Discordのクライアント内モジュールに以下のパッチを当てています。

- `getDefaultGoliveQuality()` を包んで、画面共有の capture / encode / ビットレートを固定
- メディア品質の共有オプションオブジェクト（`videoBudget` / `videoCapture` / `videoBitrate`）を差し替え
- Webカメラの `getUserMedia` 制約に `ideal` の解像度・FPSを追加

Discordクライアントの内部構造に依存するため、Discordの更新で動かなくなる可能性があります。

## 注意

- 相手（受信側）の画面共有画質を強制的に上げるものではありません。相手が配信している品質は送信側とDiscordのネゴシエーションで決まります。
- Webカメラが指定解像度・FPSに対応していない場合は、ブラウザが利用可能な値へ自動的にフォールバックします。
- ビットレートを上げすぎると回線やCPU負荷が増えます。
- Discord / Vencord の非公式改造です。自己責任で使用してください。
